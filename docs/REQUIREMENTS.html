1 · 定位与边界

一句话定位：dsh-agent-teams-concourse 是 DSH 的组织层——它把「谁和谁能通信、每个执行单元用什么模型与思考强度、任务与产出如何在层与层之间流动」变成可编辑的一等数据，用一次计划审批换运行期零审批，用几何符号换掉一切拟人化元素。

"concourse" 取「汇流」之意：多条协作路径在此汇合，而不预设某一种组织形状。项目的立论只有一句：拓扑是可编辑数据，不是代码常量；拓扑是修剪出来的，不是搭建出来的。

1.1 六条设计原则

ID原则具体动作回应的痛点
P1零美术资产包内不得含 .png/.jpg/.svg/.gif；禁头像、emoji 吉祥物、动画精灵。视觉原语只有 Unicode 几何字符、ASCII 树、表格、色块。CI 静态检查。拟人化
P2决策优先面板最上方永远是「待你决定」，且通常为空；空态显式显示「无待决事项」——让「没有需要我管的事」成为可读信息。信息杂乱
P3单行总览任何时候顶部一行说清团队状态：拓扑类型 · 顶点数 · 活跃数 · 开放边 · 预算 · 回声计数。信息杂乱
P4渐进披露流水默认折叠；任何默认折叠都必须显式说明隐藏了什么（规避「成员看起来消失了」的缺陷）。信息缺失
P5一次审批计划审批是唯一的常规审批点，运行期零审批。但破坏性操作必须确认：改拓扑 / 终止顶点 / 删任务 / 改预算 / 首次跨边界通信。审批疲劳
P6形状为主，颜色加速每个状态同时有形状与颜色；形状单独即可完整表意（色盲、灰度截图、日志、纯文本转发都可读）。严禁「只有颜色不同、形状相同」。可读性

1.3 永不做的四件事

边界理由越界判据
不做真实嵌套 concourse虚拟拓扑的表达力已覆盖复合树，真实嵌套不增表达力；且其初始化会在运行中产生新的组队审批，打断用户已批准的总计划。规格里出现「子团队再建一个 concourse」即越界（D-5）。
不做跨 DSH 实例的房间保持单进程假设；与宿主「mailbox 不保证跨进程 exactly-once」的声明一致。出现第二端口、第二进程、网络传输即越界（D-4）。
不打包任何美术资产拟人化是本品类要修的病，不是要抄的特性；且体积会拖累首屏。CI 在 files/src 全域扫到图片或 emoji 码位即失败（P1 / NFR-3）。
不做设置页面与姊妹项目同一哲学：配置只写在插件配置文件里，客户端只做只读显示。注意：本项目有 UI，但不是设置 UI。出现「设置」标签页或可写配置控件即越界。

1.4 与相邻能力的分工

第二册最重要的产出之一：现有生态是哑铃形的——一头是极廉价的工具调用，一头是极重的子代理，中间「花几千 token 搞明白一件事，然后多半就扔了」那一档没有对应物。探针补的就是这一档。

单元解决的问题产出成本量级返回方式
工具取一段已知位置的信息原文（可能落盘 + 路径）百 ~ 千 token同步进上下文
探针搞清一件与主线无关的事摘要 + 句柄千 ~ 万 token不回注，可拉取
子代理 / 成员完成主线目标的一个组成部分成果 + 可续聊会话万 ~ 十万 token异步推回上下文
一句话记住差别

子代理的返回是推送（push），探针的返回是拉取（pull）。推送意味着「不管你要不要，结果都会到达你的上下文」；拉取意味着「结果留在原地等你来取，不来取就等于不存在」。

2 · 核心架构：虚拟拓扑

2.1 图模型与 fail-closed

宿主提供的物理事实是完全图 Kn：任意两个执行单元之间都存在可达的通信信道（它们都是同一会话的直接子代理，由本插件自建邮箱投递）。concourse 的定义因此是一个带属性的有向图 G = (V, E)，其中 E ⊂ Kn 是开放的通信信道集合——不在 E 里的边即被闸门关闭。

为什么默认必须是关闭

失败模式不对称：若默认开放、忘记关闭 → 出现计划外的通信通道（静默、难发现、直接构成回声风暴风险）；若默认关闭、忘记开放 → 投递被硬拒绝并留痕，用户立刻看见并修正。

所以：物理事实是完全图，concourse 的模型是开放边集，执行时 fail-closed（deny-by-default）。

第一性质：执行底座恒为一层。所有顶点都是该会话的直接子代理，派生深度恒为 1。「层」（layer）只是对顶点施加的权限与可见性标注，不是真实的派生嵌套结构。树形外观由开放边集决定，而非由调用栈决定。

2.3 六级拓扑谱系

这六种形态不是六个功能，而是同一张完全图上不同的开放边集。

T0单体
单会话，无子代理，E = ∅。默认可得判定：任务可在一个上下文窗口内闭环
T1a单层领队
星型：所有开放边从根射出，无横向边。默认可得判定：目标可预先分解为互不协商的子任务
T1b多层领队
树形外观，但执行底座仍是一层。父子是权限与可见性标注。默认可得判定：目标需先分层再分解
T1.5混合
树 + 某个子树内部网状：开该子团队内部的横向边，其余横向边全关。默认上限判定：整体需领队，但某子团队内部需协商
T2a多领队并列
森林 + 根间横向边。只能由「会话加入」达成；根间边只承载通报与协商，不承载任务指派。需会话加入判定：多个可独立成立的目标，各需领队但需互相通报
T2b全扁平
对等网状、无根。不提供。「用户只与唯一会话对话」的前提下无根形态在交互上不成立，P2 决策优先也没有落点。不提供

T1b / T1.5 / T2a 三者，六家竞品全部不支持——这就是本项目的目标区间，而它们在虚拟拓扑下共用一个恒为一层的执行底座。

2.4 默认形态与唯一的升级路径

默认：单会话内 ≤ T1.5，绝不新开会话。用户只与唯一的一个会话（领队）直接沟通；所有其它顶点都是该会话的子代理，对用户不可见地运行。T2a 不会自动出现。

加入角色语义拓扑结果边
作为子节点新会话成为当前会话的下级，向领队汇报保持 T1.5开 leader ⇄ joined；joined 的横向边由策略决定
作为平级领队
推荐		与当前会话平级，各自带自己的子图升级 T2a开 leader ⇄ leader（notify 或 request-reply，wake 默认 never）

三条边界：① 加入的必须是已存在的会话——不提供「新建会话再加入」；② 升级 T2a 要重新走一次审批，但那是用户主动发起的，不是系统打断；③ 平级领队不互相指挥，任务指派一律沿树边向下。

2.5 成本为何不爆炸

维度真实嵌套虚拟拓扑（本方案）
执行底座深度递归派生，深度无上界恒为 1
顶点数量来源运行时由各级 sub-captain 递归决定计划期一次性声明，开工前确定
成本可预测性差：分支因子逐层相乘好：成本 ≈ f(N 顶点, 开放边数)，计划期可算
审批次数1 + 每个子团队各一次恒为 1
状态锁域 / 恢复对账每层一套，存在嵌套死锁风险单一锁域、单一一套
拓扑形状由什么决定运行时的派生结构开放边集（纯声明）

树是视图，不是机制。

3 · 六个正交旋钮

「领队中心式」与「扁平分布式」被感知为两个物种，纯粹是因为现有实现把本应正交的五个维度都选到了同一端。concourse 把它们交还给使用者；第二册又补上了第六个维度——产出如何回到父上下文。

ID维度中央端 ↔ 对等端本插件取值探针固定值
D1控制权归属中央调度 ↔ 自主认领逐顶点/逐边可选中央（父顶点指派）
D2顶点生命周期任务型 ↔ 常驻型task / residentephemeral（可晋升）
D3通信拓扑星型/树 ↔ 网状开放边集（不再是「结构怎么搭」）无横向边（只有父→子提问 + 虚的返回边）
D4上下文策略spawn ↔ 独立会话spawn（fork 未实现）spawn，可选 reference
D5失败恢复中央重派 ↔ 各自重试由领队决定不自动重试
D6产出回注策略
本册新增		全文推送 ↔ 只留句柄成员 full（推送）handle（拉取）+ tick 通知
D6 与 wake 不是一回事

wake 作用在消息投递时，方向是发送方 → 接收方，防的是打扰与回声风暴；echo 作用在产出完成时，方向是产出方 → 父上下文，防的是污染。两者独立，四种组合都有意义（例如 wake:never + echo:full = 不叫醒你，但结果直接写进你上下文）。

反直觉但重要的推论：既然五维正交，「扁平分布式」不必等于「成员常驻」，「领队中心」也不必等于「成员用完即弃」。一个需要长期记忆的代码审查组可以是「D1 中央 + D2 常驻 + D3 星型」——现有插件无法表达，因为它们把 D2 焊死在任务型上。

4.4 旁路探针（FR-D）

定义：旁路探针（Probe）是当前会话内即时创建、上下文隔离、产出默认不回注、可遮蔽可丢弃的临时执行单元。它由一个旁路问题触发，交回一份摘要，留下一个可寻址的句柄。它是 concourse 图上的一个新顶点类，不是第二个插件（D-1）。

两条最容易被实现坏的纪律

① 零回注是代码纪律，不是配置。只要任何一条代码路径把探针结果当成 tool result 返回，回注就发生了。必须把「绝不返回探针产出」写成该模块的硬不变量，并配自动化断言（AC-1）。

② 「不污染」与「可丢弃」是两个机制。前者是准入控制（默认不回注），后者是事后收容（遮蔽已进入的内容）。把它们都叫「删除」是现有实现的通病，结果是两边都做不好。

  ◇ 探针 p4 · Vite 的 base 配置会不会影响子路径资源  ✓ 完成 · 2.3k tok · 未回注   [取回]
  ↑ 这一行就是 tick 档的全部成本（约 15–25 token）；silent 档完全不出现

三态徽章「已回注 / 仅句柄 / 已遮蔽」是这一屏存在的理由——没有它，用户无法知道模型此刻究竟看得见什么。探针与成员在同一份名册里（AC-5），但用分组与更小的视觉权重区分：同一等公民，不是同一量级。

6.2 Probe 记录（新增）

字段类型说明
idstring句柄，会话内唯一。p1, p2…
questionstring旁路问题原文
stateenumdraft / running / done / adopted / shadowed / promoted / discarded
parentVertexstring挂载的父顶点 id，不允许为 null
originhuman | model触发方（配额策略依赖它）
echo / echoNotifyenum回注策略与通知档
summary / fullTextstring | null摘要 / 全文（按需加载）
sourcesarray溯源：文件路径 / URL / 会话引用，每条带「它是怎么被用到的」
usage / echoTokensobject / number消耗与实际回注进父上下文的 token 数（算 echo_ratio）
createdAt / endedAt / expiresAt / shadowedAttimestamp生命周期时间戳
promotedTostring | null晋升后的成员 id

Probe 不是 Vertex 的子类：它借用 budget / model / toolFilter，但不进图的邻接表——没有出边，唯一入边来自父顶点；也不出现在任务 DAG 中（无 dependencies / acceptance / kind）。晋升时发生一次转换：创建真正的 Vertex 记录并把摘要/溯源转为初始记忆。

7 · 验收判据

7.1 团队层（V-1 … V-5）

ID命题证据形态状态
V-1拓扑是可声明的数据：T1a / T1b / T1.5 由开放边集裁剪表达，执行底座深度恒为 1fixture 矩阵 + 真机 T1a/T1b 冒烟达成
V-2每个顶点独立的 model / reasoningEffort / toolFilter 真实生效（台账 requested = effective）运行时探针 + 装配透传测试达成
V-3闭边消息在收件侧被拦截并留痕；wake 默认 never；去重 / 速率 / 预算熔断生效四入口绕过矩阵 + 真机拦截原文；TTL 仍为非硬保证（H3.1）部分
V-4全局一次审批：计划批准后运行期零组队审批打断生命周期转换测试 + 作用域测试达成
V-5UI 零图片资产，形状单独可辨，单行总览 + 待决置顶资产门禁 + jsdom 结构断言达成

7.2 探针层（AC-1 … AC-5）

ID判据怎么算通过状态
AC-1旁路过程的零污染一次探针从发起到结束，主会话上下文长度不因它的探索过程而增长。可验证形式：探针跑掉 5 万 token，主线增长 0未开始
AC-2摘要在默认档位也不自动进入探针完成后，默认配置下主模型不知道摘要内容；只知道「有这么一条，地址是 X」未开始
AC-3模型可按地址主动取回主模型能通过一个工具按句柄把摘要读进上下文——且这次读取是它自己的决定，不是系统的未开始
AC-4人可丢弃，且「遮蔽」与「删除」可区分UI 上有丢弃动作；丢弃后模型看不到；遮蔽态在 UI 仍可查、可恢复，硬删才有不可逆语义未开始
AC-5一等公民的呈现与晋升通道探针在 UI 里的呈现形态与成员一致（同一份名册、同一套状态徽章），并可「提升」为常驻成员未开始

7.3 量化判据（不接受口号）

指标阈值为什么是这个数
echo_ratio = 回注 token / 探针消耗 token< 1%（handle 档；tick 档实测约 0.1%）零污染必须可计量，否则不可验收
单次取回上限默认 2000 token（可配）防「取回」本身变成新的污染入口
tick 通知成本15–25 token20 token 换「模型知道该不该去取」，是四个数量级的杠杆
计划期容量校验超并发/超预算在计划期报错，不运行到一半失败宿主默认 maxActiveSubagents = 8、maxDepth = 1
kernel 覆盖率行/分支 ≥ 90%纯函数内核是整个产品的信任基础
测试基线349/349（44 文件）任何交付不得让数字下降

8 · 不做与延后

项处置理由
T2b 全扁平（无根网状）不提供「用户只与唯一会话对话」前提下无根形态在交互上不成立
真实嵌套 concourse永不不增表达力，且会引入运行期二次审批（D-5）
跨 DSH 实例房间永不保持单进程假设（D-4）
与 nanmicoder 的兼容层 / 迁移桥不做该插件将被卸载；agent_teams_* 命名空间不复用（D-9）
设置页面 / 可写配置 UI永不配置只在插件配置文件里（§1.3）
contextMode: fork（带父记忆 seed）延后 P7MVP 只做 spawn；fork 需要父历史 seed 语义
LLM 精修建议延后 P7启发式必须先在真实语料上站住（D-6：失败即回落）
飞行中改拓扑延后 P7需走 P5 确认清单，先有稳定运行期
探针触发建议（模型何时该开探针）延后 P8+系统性优化，不进首个探针版本
跨会话探针共享 / 与 ACP 压缩的交互延后需先有稳定句柄注册表
