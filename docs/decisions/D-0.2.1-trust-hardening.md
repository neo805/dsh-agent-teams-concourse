## 决议

0.2.0 的“收件箱准入”在代码里没有真实宿主入口：旧绕过矩阵只是反复调用同一个
`admitInbound`。本批次将权威判定落到宿主真实存在的 `agent/pre-step` 模型准入事件：

- 消息来源使用宿主 durable `agent-message.senderSessionId`，不信任工具参数。
- `team_send` 使用真实 `exec.agent` 作为身份凭据；`from` 与 live Agent 不一致时拒绝。
- 官方 `send_message`、裸 `ctx.subagents.sendMessage` 生成同一来源结构，统一在目标
  Agent 的 pre-step 被过滤；闭边消息移除并写 `comm/reject`。
- 该闸门语义是“消息不进入模型”，不是删除已提交的会话 inbox 事件；需求口径以
  本文件的边界为准，不宣称物理删除。

## 四组修复

1. **T0 真实路径**：`filterInbound` 按唯一 sender 反查 concourse；同一领队下多个
   concourse 不共享身份归属。未登记 sender fail-closed 为 `UNKNOWN_VERTEX`。
2. **T1 投递事务**：`evaluateInbound` 只读预检，`commitInbound` 在真实写入目标 Agent
   inbox 后才扣预算/去重/记 deliver；失败写 `delivery-failed`。降级消息以
   `wakeup=false` 真实入 inbox，并记 `comm/degrade`，不再丢消息。
3. **T2 恢复与原子性**：`Ledger` 从事件快照恢复 seq/query/echo；生命周期先写盘成功再
   发布内存状态；`edge-open/close` 由 live 与 replay 共用 reducer；approve 的每次
   vertex-start 落盘失败触发已启动顶点回滚。
4. **T3 审批并发**：同一 concourse 的第二次 approve 返回 `APPROVAL_IN_PROGRESS`；
   `exec.signal` 透传 startActivation，启动之间检查取消并复用回滚。
5. **T4 一致性**：工具/UI 统一有向边容量 `n(n-1)`；预算回填后复查溢出；拆分
   concourse/edge/vertex 预算键集；`storagePath` 明确为 JSONL 文件路径，缺省内存。
