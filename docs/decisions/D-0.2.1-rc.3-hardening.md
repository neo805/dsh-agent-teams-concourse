## 背景

rc.2 的测试全绿掩盖了三类契约漂移：

1. 客户端 keyed slot 实际要求 `key`，代码与测试却固定为 `id`；
2. `vertexId` 只在 concourse 内唯一，但 substrate 把它当全局键；
3. 通信提交、限流窗口和回放预算存在不同源，测试没有跨边界断言。

本轮只修可由局部回归确定的问题，不把跨 JSONL / Agent inbox 的 exactly-once 伪装成
一次小修。

## 决议

1. **UI 契约以当前 Client Inspect 为准**：`sidebar.right.pane.tab` 使用 `key`；
   页型 disposer 交给 `ctx.effect`；降级保留 warning。
2. **运行时身份以 childId 为键**：parent/activation 表按 childId 索引；dispose 成功
   后才删除；RVE 查询使用 `(concourseId, vertexId)`。
3. **通信账目单一提交段**：deliver/degrade 都是真实投递，都扣一次预算；预检捕获
   唯一时间戳，提交不重新翻转 verdict；改边保留未变 rate limiter。
4. **回放与 live 共用预算 reducer**：边事件同时归约拓扑与 edgeBudgets；createdAt 取
   create 事件时刻。
5. **计划管线单一规范化**：预算回填下沉 kernel；Catalog 预检在 approve 任何副作用前。
6. **门禁正向声明**：依赖方向用 allowDirs 白名单；corpus 用原始计数比例且拒绝旧
   dist；pack 核对实际解包文件；资产门禁覆盖 dist。
7. **内核输入安全**：复合键 JSON tuple、own-key/null-prototype、task id 唯一、effort
   单一归一化、ASCII 词边界。
8. **只做等义清理**：一次 load、目录只确保一次、Ledger 派生索引、删除 order/未用
   tool 依赖字段；保留同步 sink-first 与 CJS 宿主格式。

## 明确不在本轮修复

以下问题需要事件格式或宿主对账协议，已登记开发计划 §9：

- `approve` 中断恢复与 Activation adopt；
- 真实投递成功后 commit/写盘失败；
- dedup/admission 的完整 replay；
- `team_plan` create+submit 的部分成功；
- archived 通信边界与 ticket 上下文绑定；
- JSONL torn-tail 策略。

本轮文档只承诺“可检测的局部一致性”，不承诺 exactly-once 或完整崩溃恢复。
